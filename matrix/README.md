# Собственный мессенджер для заявок (Matrix)

Приватный сервер на вашем Mac (Apple Silicon), одно приложение Element на телефоне,
внутри отдельное пространство под каждый проект. Заявки из любых систем приходят
на вебхук и публикуются в комнату проекта от имени его бота.

```
Сайт / CRM / n8n / форма  --POST /hook/<проект>-->  шлюз  -->  Synapse (Matrix)  -->  Element на телефонах
```

Состав (всё в `docker-compose.yml`):

| Сервис    | Что делает                                                        |
|-----------|-------------------------------------------------------------------|
| synapse   | Сервер Matrix. Федерация выключена, регистрация закрыта           |
| postgres  | База данных Synapse                                               |
| element   | Веб-клиент, открывается по адресу сервера                        |
| gateway   | Шлюз вебхуков `/hook/<slug>` (Node, без зависимостей)             |
| caddy     | HTTPS с автоматическим сертификатом Let's Encrypt, маршрутизация  |
| bootstrap | Одноразовая утилита: создаёт админа, ботов, пространства, комнаты |

## Что нужно заранее

1. Mac с установленным [OrbStack](https://orbstack.dev) или Docker Desktop.
2. Домен, например `chat.vitolux.ua`, с A-записью на ваш внешний IP.
   Если IP динамический, используйте DDNS (у большинства роутеров есть встроенный).
3. На роутере проброс портов 80 и 443 на Mac. Порт 80 нужен только для выпуска сертификата.
4. В настройках macOS выключить сон (Системные настройки, Экономия энергии,
   «Предотвращать автоматический переход в режим сна»).

## Установка

```bash
cd matrix
cp .env.example .env            # заполнить домен, пароли, секреты
cp bootstrap/projects.example.json bootstrap/projects.json   # вписать свои проекты
./init.sh                       # ключи Synapse, конфиги из шаблонов
docker compose up -d            # запуск сервера
docker compose run --rm bootstrap   # создать админа, ботов, пространства, комнаты
```

Секреты для `.env` удобно генерировать так: `openssl rand -base64 32`.

`bootstrap` в конце печатает URL и секрет вебхука для каждого проекта и пример `curl`.
Эти же данные лежат в `data/gateway/projects.json`. Скрипт идемпотентен: добавили проект
или сотрудника в `projects.json`, запустили ещё раз, он досоздаст только новое.

Затем:

- Откройте `https://chat.ваш-домен` в браузере и войдите под `ADMIN_USER`.
- На телефон поставьте Element (App Store / Google Play), на экране входа укажите адрес
  вашего сервера вместо matrix.org.
- Сотрудникам отправьте их логин и разовый пароль из вывода `bootstrap`, попросите сменить.

## Формат projects.json

```jsonc
{
  "projects": [
    {
      "slug": "naos",                      // часть URL вебхука: /hook/naos
      "name": "Наос",                      // имя пространства
      "bot_name": "Наос · Заявки",         // как подписаны сообщения
      "avatar": "avatars/naos.png",        // необязательно
      "rooms": { "default": "Все заявки", "calls": "Звонки" },
      "members": ["ivan", "olena"]         // логины сотрудников проекта
    }
  ]
}
```

- Один проект = одно пространство + свой бот + свои комнаты. Сотрудник видит только те
  проекты, где он указан в `members`. Админ из `.env` добавляется во все.
- `rooms` задаёт каналы проекта. Ключ `default` обязателен, в него идут заявки без поля
  `channel`. Остальные ключи выбираются полем `channel` в вебхуке.

## Как отправить заявку

```bash
curl -X POST https://chat.ваш-домен/hook/naos \
  -H "X-Hook-Secret: СЕКРЕТ_ПРОЕКТА" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Заявка с сайта",
    "source": "naos.ua",
    "channel": "default",
    "fields": { "Имя": "Иван", "Телефон": "+380501234567", "Комментарий": "Перезвоните после 18" },
    "url": "https://crm.example.com/leads/123"
  }'
```

Все поля необязательны. Шлюз принимает JSON и `application/x-www-form-urlencoded`
(удобно для Tilda и подобных конструкторов). Секрет можно передать тремя способами:
заголовок `X-Hook-Secret`, `Authorization: Bearer ...` или `?key=...` в URL.

| Поле      | Назначение                                                       |
|-----------|------------------------------------------------------------------|
| `title`   | Заголовок сообщения                                              |
| `text`    | Произвольный текст, переводы строк сохраняются                   |
| `html`    | Готовый HTML (вместо `text`)                                     |
| `fields`  | Объект «подпись: значение», выводится списком                    |
| `url`     | Ссылка «Открыть заявку»                                          |
| `source`  | Откуда заявка (сайт, звонок, форма)                              |
| `channel` | Ключ комнаты из `rooms` проекта                                  |
| прочие    | Любые другие поля верхнего уровня выводятся как «ключ: значение» |

Исходный JSON заявки сохраняется в событии Matrix (ключ `ua.vitolux.lead`): он пригодится
для кнопок «Взял / Перезвонил» и для интеграций в будущем.

## Подключение этого сайта

В админке VitoluxUA, раздел «Налаштування», блок «Власний месенджер (Matrix)»: вставьте URL
и секрет проекта `vitolux`, включите сповіщення и нажмите «Надіслати тестове повідомлення».
Новые заказы идут в канал `orders`, смены статусов в `status` (см. пример проекта
`vitolux` в `projects.example.json`). Telegram при этом можно оставить включённым,
оба канала работают параллельно.

Для уже развёрнутой базы добавьте настройки:

```sql
INSERT INTO settings (setting_key, setting_value, setting_type) VALUES
('matrix_webhook_url', '', 'string'),
('matrix_webhook_secret', '', 'string'),
('matrix_notifications_enabled', 'false', 'boolean')
ON DUPLICATE KEY UPDATE setting_key = setting_key;
```

## Приватность: что остаётся снаружи

- **Содержимое заявок** никуда с вашего Mac не уходит. Федерация выключена,
  к matrix.org сервер не обращается, превью ссылок отключены.
- **Пуш-уведомления.** iPhone получает пуши только через серверы Apple, Android обычно
  через Google. В конфиге стоит `push.include_content: false`: наружу уходит только сигнал
  «есть новое сообщение», текст приложение забирает с вашего сервера. Официальный Element
  использует для этого пуш-шлюз Element, он видит факт уведомления, но не текст.
  На Android можно обойтись и без Google: Element поддерживает UnifiedPush,
  поднимите [ntfy](https://ntfy.sh) рядом в том же compose.
- **Let's Encrypt** видит только имя домена при выпуске сертификата.

## Эксплуатация

```bash
docker compose logs -f gateway                # кто и куда отправлял заявки
docker compose pull && docker compose up -d   # обновление
tar czf backup-$(date +%F).tgz data/          # бэкап (БД, медиа, ключи, конфиг шлюза)
```

Бэкапить обязательно `data/synapse/*.signing.key` и `data/gateway/projects.json`:
без первого сервер не поднять с тем же именем, без второго потеряются токены ботов.

Проверка шлюза без секрета: `curl https://chat.ваш-домен/hook-health`.

## Локальная проверка без сервера

```bash
cd gateway && node --test       # тесты шлюза на фальшивом Matrix
```

## Что можно добавить дальше

- Кнопки под заявкой («Взял», «Перезвонил», «Спам»): бот читает реакции и дёргает ваш API.
- Ответ сотрудника в треде уходит клиенту на почту или в SMS через тот же шлюз.
- Мосты к WhatsApp, Instagram, Telegram (mautrix): переписка с клиентами в тех же
  пространствах. Работают через неофициальные API, требуют присмотра.
